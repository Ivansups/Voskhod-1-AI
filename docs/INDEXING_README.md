- ✅ **Автоматическая индексация** при запуске системы
- ✅ **Инкрементальная индексация** по умолчанию
- ✅ **Отдельный сервис индексации** в Docker
- ✅ **Мониторинг в реальном времени**
- ✅ **Работа без внешних зависимостей**

## 🎯 Новая логика индексации (v2.0)

### 🚀 Что изменилось

**Раньше:** Каждый запуск `run_indexing.sh` всегда удалял всю векторную базу и индексировал все документы заново.

**Теперь:** Система проверяет актуальность данных и выполняет только необходимые операции:

### 📊 Режимы работы

#### 1. **Инкрементальная индексация** (по умолчанию)
- ✅ Проверяет, есть ли уже актуальные данные в БД
- ✅ Если данные актуальные (>1000 документов) - пропускает индексацию
- ✅ Добавляет только новые или измененные файлы
- ✅ Сохраняет существующие вектора

#### 2. **Полная переиндексация** (принудительная)
- 🗑️ Очищает всю коллекцию
- 🔄 Индексирует все документы заново
- 💪 Используется после серьезных изменений

## 🐳 Docker скрипты (рекомендуется)

### `scripts/start-with-indexing.sh` - Полный запуск с индексацией
```bash
./scripts/start-with-indexing.sh
```
- 🚀 Запускает всю систему автоматически
- 📊 Выполняет начальную индексацию
- ⏰ Мониторит процесс в реальном времени
- 🎯 **Рекомендуется для первого запуска**

### `scripts/docker-indexing.sh` - Управление индексацией
```bash
# Одноразовая индексация (умная)
./scripts/docker-indexing.sh

# Принудительная полная переиндексация
./scripts/docker-indexing.sh force

# Автоматический мониторинг (работает в фоне)
./scripts/docker-indexing.sh monitor
```

## 🏗️ Docker сервисы

### Сервис `indexer`
Отдельный контейнер для индексации документов:
- **Образ**: Тот же, что и у API
- **Команда**: `python3 indexer.py`
- **Режимы работы**:
  - `once` - одноразовая индексация (по умолчанию)
  - `force` - принудительная полная индексация
  - `monitor` - автоматический мониторинг и переиндексация

### Автоматический запуск
```bash
# Запуск с индексацией
docker-compose --profile auto-indexer up -d

# Только индексация
docker-compose --profile indexer run --rm indexer
```

## 🔧 API изменения

#### Эндпоинт `/v1/admin/sync`
```http
POST /v1/admin/sync?force=true
```

Параметр `force`:
- `force=false` (по умолчанию) - инкрементальная индексация
- `force=true` - полная переиндексация

### 📈 Когда нужна полная переиндексация

✅ **Обязательно после:**
- Исправления багов в парсерах
- Изменения модели эмбеддингов
- Серьезных изменений в коде индексации

✅ **Рекомендуется после:**
- Добавления большого количества новых документов
- Изменения настроек chunking'а

❌ **НЕ нужна:**
- При регулярных обновлениях git репозитория
- При небольших изменениях в существующих документах

### 🔍 Мониторинг

Система предоставляет подробный статус индексации:
```bash
curl http://localhost:8000/v1/admin/sync/status
```

Возвращает:
- `phase`: idle, syncing, indexing, ready, error
- `progress`: процент выполнения (0-100)
- `documents_count`: количество документов в БД
- `files_processed/total_files`: прогресс обработки файлов

### 💾 Безопасность данных

- **Инкрементальный режим** сохраняет существующие вектора
- **Полный режим** требует явного подтверждения
- **Проверка статуса** позволяет увидеть текущее состояние перед действиями

### 🚀 Быстрый старт

1. **Проверь статус:**
   ```bash
   ./scripts/check_indexing_status.sh
   ```

2. **Если система не готова - запусти индексацию:**
   ```bash
   ./scripts/docker-indexing.sh
   ```

3. **После серьезных изменений - полная переиндексация:**
   ```bash
   ./scripts/docker-indexing.sh force
   ```

### 📊 Производительность

- **Инкрементальная индексация:** 2-5 минут (только новые файлы)
- **Полная индексация:** 25-35 минут (все документы)
- **Проверка статуса:** < 1 секунды
